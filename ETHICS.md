# ETHICS.md

## 1. What was analysed, and how

The subject of analysis is **G\*Power 3.1.9.x**, a statistical power-analysis
program distributed free of charge for academic use by the Heinrich-Heine
University Düsseldorf.

The analysis method is **black-box behavioural probing**: the program is run
through its own user interface, inputs are supplied, printed outputs are
recorded, and candidate models of the input→output map are discriminated
against each other. No attempt was made to disassemble, decompile, patch,
unpack or otherwise inspect the binary, and none is documented here.

Concretely, G\*Power **3.1.9.6 for macOS**, downloaded from the authors'
page as distributed (notarised, signed by its author), was run on the
student's own machine and operated through the **macOS Accessibility API** —
the interface screen readers use — by `tools/gpower_ax.py`. The tool selects
menu entries, types into the labelled input fields, presses *Calculate*, and
reads the printed output panel and any dialog. It does not read process memory,
load the binary, or open any file inside the application bundle. The
application stayed outside the repository throughout.

What is recorded (`probes/observations/`) is only what the program printed in
its output panel for a given input: a few numbers per run. Recording observed
outputs of a published program as test expectations is what any conformance
suite does.

This is interoperability analysis of observable behaviour — the same activity
as writing a test suite against a program you did not write.

## 2. What this repository does not contain

Four hard rules, each enforced by `python tools/compliance_check.py` and run
on every CI build:

| rule | enforcement |
|---|---|
| **No G\*Power binary or installer.** `GPower.exe`, `.dmg`, `.msi`, `.zip` distributions and any executable artefact. | `C-1` — filename and extension scan |
| **No decompiler or disassembler output.** No `sub_401A20`-style symbols, no `__fastcall` signatures, no register-level listings, no tool banners. | `C-2` — regex scan of every text file |
| **No copied source.** G\*Power's source is not published; none of it is here. The implementation was written from `SPEC.md`. | [CLEANROOM-PROTOCOL.md](docs/CLEANROOM-PROTOCOL.md) |
| **No G\*Power output under `src/`.** The one data file is generated by this engine and independently re-derived by the test suite. | `C-4`, `make_vectors.py --check` |
| **The evidence files are intact.** They carry Greek letters and non-ASCII text and they are the deliverable; a re-encoding accident would corrupt them silently. | `C-5` |

The probe worksheet under `probes/` holds *predictions* generated by this
engine before any observation, plus an `observed` column filled from the
recorded readings. The readings are never used to generate engine code or the
bundled vectors (`C-4`); they are used only to **test** the engine
(`tests/test_gpower_observed.py`).

## 3. What this software is not

**This is not G\*Power, is not affiliated with its authors, and is not endorsed
by them.** It is an independent implementation of a documented specification
covering **one** of G\*Power's test families.

The claim is bounded and it is stated in machine-readable form, so an agent
quoting a number also quotes the caveat:

```console
$ gpower --version
gpower 1.0.0 (SPEC.md v1.0)
```

```json
// MCP tool: engine_provenance
{
  "engine": {
    "name": "gpower-rea", "version": "1.0.0", "spec": "SPEC.md v1.0",
    "contains_decompiler_output": false,
    "bundles_original_binary": false
  },
  "method": "Behavioural (black-box) reverse engineering ... Findings are
             catalogued in SPEC.md and docs/EVIDENCE/ ..."
}
```

The agent's system prompt contains the instruction explicitly:

> *"Do not claim to be G\*Power; you are an independent engine built to a
> documented specification."*

## 4. Why reimplement at all

The honest answer, because "because the assignment said so" is not one.

G\*Power has no command line, no API and no scriptable interface. The
consequences for research practice are concrete:

* **Power analyses are not reproducible.** A methods section says "computed in
  G\*Power"; nobody can re-run it. A command in a repository can be re-run by
  a reviewer in one second.
* **They cannot be checked in bulk.** A systematic review that wants to verify
  the power calculations of 300 trials has no mechanical route.
* **They cannot be automated.** Study-design pipelines, registry templates and
  protocol generators all stop at a GUI.
* **An AI assistant can only drive it by screenshotting and clicking** — slow,
  expensive, and silently unreliable, because the agent is reading pixels
  rather than numbers.

A free, dependency-free, scriptable engine with a published specification and a
conformance gate removes all four limits. That is additive to G\*Power, not
competitive with it: the GUI remains the better tool for a researcher exploring
a design interactively, and this remains the better tool for a pipeline, a
reviewer, or an agent.

## 5. Responsible use of the agent

The agent (`agent/agent.py`) is a convenience layer over the same engine, and
it is constrained to stay one:

* **It may not do arithmetic.** Its system prompt forbids stating any number
  that did not come back from a tool call, and `compliance_check.py` C-3 fails
  the build if the agent file contains arithmetic at all.
* **It must name its assumptions.** When the user is silent, it applies
  `α = 0.05`, `power = 0.80`, two tails, allocation ratio 1 — and says which
  of those it defaulted.
* **It must not invent a design.** Choosing between a paired and an
  independent-groups test is a substantive methodological decision; the prompt
  requires the agent to name the design back to the user and to ask when the
  reading is genuinely ambiguous.
* **Its answers are reproducible.** Every number it reports can be reproduced
  by a `gpower solve` command through a different code path — and that
  equivalence is a test, not a promise
  ([VALIDATION.md §5](docs/VALIDATION.md#5-interface-equivalence)).

A power analysis is an input to decisions about human participants. The
appropriate use of this tool is to make such a calculation *auditable*, not to
remove a statistician from the loop.
